# Project Rules

## 목적

이 프로젝트는 소규모 도서 대출 서비스를 대상으로 소프트웨어공학의 이해와 활용을 학습하기 위한 실습형 시스템이다.

## 필수 아키텍처 규칙

- 전체 실행 환경은 `Docker Compose`를 기준으로 구성한다.
- 메인 서비스는 `Spring Boot` 기반으로 구현한다.
- 메인 서비스는 `3-Layer Architecture`와 `MVC`를 함께 적용한다.
- 기능은 `book`, `member`, `loan` 단위로 분리한다.
- 각 기능은 `presentation`, `business`, `dataaccess` 계층으로 분리한다.
- View는 서버 렌더링 중심으로 구성하며 `Thymeleaf`를 우선 사용한다.
- `HTML`, `CSS`, `JS` 파일은 반드시 분리한다.
- 핵심 비즈니스 로직은 `JS`가 아니라 서버의 `business`, `dataaccess` 계층에 위치해야 한다.

## 기술 기준

- Java 버전은 `21`을 사용한다.
- Spring Boot는 `3.x` 계열을 사용한다.
- 빌드 도구는 `Maven`을 사용한다.
- 운영 DB는 `PostgreSQL`을 사용한다.
- 초기 개발과 빠른 테스트를 위해 `H2` 프로필을 허용한다.
- DB 스키마 관리는 `Flyway`를 기본으로 검토한다.

## 메인 서비스 규칙

- 도서 관리, 회원 관리, 대출 관리 기능을 제공한다.
- Controller는 요청/응답 조립만 담당한다.
- Service는 비즈니스 규칙과 트랜잭션 경계를 담당한다.
- Repository 또는 DAO는 데이터 접근만 담당한다.
- Controller에서 직접 SQL 또는 Docker 제어를 수행하지 않는다.

## 모니터링 서비스 규칙

- 모니터링 서비스는 메인 서비스와 분리된 별도 Docker 컨테이너로 구성한다.
- 모니터링 서비스는 메인 서비스와 DB의 상태를 REST 기반으로 수집한다.
- 메인 서비스 로그를 수집하여 Dashboard에 출력한다.
- 장애 탐지, 장애 이력, 상태 변화 이력, 지표 계산을 담당한다.
- Dashboard는 기능별 탭 구조로 분리하여 제공한다.

## Docker 제어 규칙

- `docker.sock` 접근은 Compose 서비스 `service-monitor`에만 허용한다.
- Docker 제어는 고위험 기능으로 취급한다.
- Docker 제어는 관리자 인증 후에만 수행한다.
- Docker 제어 대상은 allowlist로 제한한다.
- Docker 제어 명령은 allowlist로 제한한다.
- `exec`, 임의 컨테이너 생성, 임의 이미지 조작은 기본 범위에서 금지한다.
- Docker API 접근은 `dataaccess` 계층 내부 어댑터를 통해서만 수행한다.

## 신뢰성 및 장애 주입 규칙

- 모니터링 서비스는 각 컨테이너의 장애 유무를 탐지한다.
- 모니터링 서비스는 `MTBF`, `MTTR`, `MTTF`, `Availability`를 계산한다.
- 계산 결과는 Dashboard에 표시한다.
- 장애 주입 기능은 실습 목적의 제어된 관리자 기능으로 제공한다.

## AI-Ops 규칙

- AI-Ops는 기본 구현이 아닌 `Optional` 기능이다.
- AI-Ops는 로그 추적, 오류 수집, 원인 분석, 대응 제안을 목표로 한다.
- 1차 분석은 규칙 기반 RCA를 사용한다.
- 외부 LLM 연동은 확장 가능한 구조로 준비하되, 기본 구현 범위에 포함하지 않는다.
- AI 분석 결과는 운영 보조 정보로 취급하며 자동 의사결정의 단독 근거로 사용하지 않는다.

## 문서 규칙

- 구현 전에 규칙과 구조를 문서로 고정한다.
- 설계 변경, 패키지 변경, 보안 정책 변경, 운영 정책 변경 시 관련 문서를 즉시 갱신한다.
- Optional 기능은 기본 기능과 별도로 범위를 명확히 기록한다.
